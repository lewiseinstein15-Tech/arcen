2 · The four-layer architecture

L1AGENTS
DRAFT · FORGE · TEMPER — the only three agents that decide
Planner opens every turn and re-plans on failure · executor runs one tool step at a time · verifier tests adversarially and reports pass/fail.
src/arcen/agents/draft.pyforge.pytemper.py
L2SUB-AGENTS
500+ task-named sub-agents, spawned on demand (TEST-READER, MIGRATOR, …)
Fan out for research, exploration and bulk edits; depth cap = 2, concurrency cap = 8; torn down when done; observations report back into the same stream.
src/arcen/subagents/agent.pyevents: spawn · spawn.done
L3CAPABILITY
Skills (10k+) · Tools (1k+) · MCPs (300+) · Plugins (100+) · Memory graph
One Tool Protocol with JSON Schema generated from type hints · progressive SKILL.md loading · lazy MCP state machine · six plugin hook points · SQLite entity graph with decay and consolidation.
src/arcen/tools/skills/mcp/plugins/memory/
L4RUNTIME
Per-session Docker sandbox (or honest process fallback) · FastAPI · NDJSON stream · session jsonl · config vault
Everything executes inside the sandbox; every event is append-only to the session log and fanned out over HTTP as one JSON object per line with seq + ts.
src/arcen/sandbox/server/stream/session/config.py
